# 验证范围

本仓库把作者本地已经使用的共享文件队列与结果事件监听整理成可配置版本。仓库发布准备时的脚本测试使用独立目录和合成数据，不调用 WorkBuddy 或 Codex 模型。

## 自动测试检查什么

- 原子发布、ID 预留、重复提交拒绝、领取、结果归档、哈希验收记录。
- 越界路径、目录联接、凭证路径、无效 JSON、失败结果验收等负向情况。
- 结果事件、相同内容去重、成果改变、既有验收基线、重复实例、正常停止。
- 队列投递失败后同内容不自动重试；重新启动后仍保留这个边界。
- 运行于含空格和中文的路径；Windows PowerShell 5.1 与 PowerShell 7。

具体执行记录由 `tests/run-tests.ps1` 输出，保存在被忽略的 `.test-runs` 中。GitHub Actions 提供远端测试结果；本地通过不等于远端 CI 已通过。

## 不从这些测试推断什么

自动测试不证明本次可配置版本已在其他电脑完成真实 WorkBuddy 领取、原生会话回调、模型额度、业务成果质量、正常退出重开或系统重启后的恢复。旧方案、其他网关和其他版本的实测结果不能移作此版本的验收证据。

## 新用户的实际验收

1. 在授权项目发送一个可核对的小文件任务。
2. 在真实 WorkBuddy 会话中看到领取及自身工具执行，核对实际文件。
3. 看到 results、结果监听 queued 和绑定的 Codex 聊天实际收到请求。
4. 由 Codex 检查内容，生成 reviews 并在聊天中报告真实结论。
5. 发送下一项独立小任务验证守候已重新建立；若需要重开恢复，另作一次正常重开后的任务验收。

只有相应步骤有证据时，才对该步骤报告成功。不承诺固定秒数、不以执行方自述替代来源证明，不声称无需联网或免费。
